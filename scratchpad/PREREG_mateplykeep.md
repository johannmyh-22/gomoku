# 预登记：`mateplykeep` 大样本重测（LV5）

**本文件在数据产生之前提交。** 提交哈希即时间戳，用于证明判定规则不是看到结果之后才定的。
本项目反复栽在「先看结果再编解释」上（见 PROGRESS「一之三」的 +6 故事、「一之二」的
+90 Elo），预登记是唯一能从流程上堵住这个坑的办法。

---

## 一、要检验的假设

**H1**：在 LV5 出厂配置下，`mateplykeep`（杀棋分 ply 校正 + 主搜索置换表跨步保留）
比出厂引擎强。

**H0**（零假设）：两者棋力相同，胜率 50%。

## 二、为什么要重测（前一轮的结果与其不足）

第一轮（2026-08-09，种子 20260811，48 局）：

| | 结果 |
|---|---|
| 对照 `orig` vs `orig2` | **6 : 6**（12 局）——噪声底干净 |
| `mateplykeep` vs 出厂 | **29 : 19**（48 局） |

z = 1.44σ，双侧 p = 0.149，点估计胜率 60.4%（≈ +73 Elo），
**95% 置信区间 −24 ~ +184 Elo**。

**未达标**：开跑前定的线是 ≥2σ。且本项目先例更严——LV4 的 VCT TT「+6」在 1.22σ 时被
**撤回**，`rootsort` 在 0.73σ 时**不合入**。1.44σ 不能反过来宣称有收益。

第一轮的定位因此是**假设生成（hypothesis-generating）**，不是证据。本轮是独立重测。

## 三、判定规则（**本轮开跑前锁定，不得修改**）

1. **主分析**：只看本轮**新数据**，不与第一轮的 48 局合并。
   理由：第一轮的数据已经被看过，合并后再判显著等于优化停止点（optional stopping），
   置信区间会假性收窄。第一轮已降格为假设生成。
2. **样本量固定 200 局**（100 个开局 × 双色），**中途不看结果、不提前停、不追加**。
3. **开局种子换成 20260812**（第一轮是 20260811）。同一批开局重复使用会让新旧数据不独立。
4. **对照必须 6:6**（12 局，`orig` vs `orig2`）。不是 6:6 则本轮全部作废，
   说明还有未消除的随机源，不得对 A/B 数据做任何解释。
5. **被测配置逐项等于 `index.html` 的 `LEVELS[5]`**：
   `timeMs:9000, maxDepth:18, vcfDepth:20, vcfBudget:1200000, vctDepth:9,
   vctBudget:1500000, vctDefDepth:7, vctDefBudget:150000, rand:0, rootFilter:true`。

### 结论如何下（阈值写死）

设本轮 `mateplykeep` 胜 w 局、负 l 局、分胜负 n = w + l，
z = (w − n/2) / (√n / 2)。

| z | 判定 | 动作 |
|---|---|---|
| **z ≥ 2.0** | 证实 H1 | **合入 `index.html`**，PROGRESS 记为本项目第一次可证实的棋力提升 |
| **−2.0 < z < 2.0** | 未能证明 | **不合入**，记入「试过但无收益」表。**不得再追加局数** |
| **z ≤ −2.0** | 反向证实 | **不合入**，记明 TT 跨步保留在 LV5 有害 |

### 明确禁止的操作

- 跑到一半看比分，觉得偏正就加局数、觉得偏负就提前停
- 把本轮与第一轮合并后再挑一个让结果显著的口径
- 结果不显著时，事后改判定阈值、改分析人群、或换一个「其实我们真正想测的是……」的指标
- 若因容器回收等外部原因中断：按**实际完成的局数**用同一个 2σ 阈值判定，
  并在 PROGRESS 里标注「样本量未达预登记的 200 局，功效不足」。
  **不得**把中断点当作有利的停止点来解释。

## 四、功效说明（诚实的预期）

以第一轮点估计 60.4% 为真值，200 局达到 2σ 的功效约 **83%**。
若真实效应只有 55%（≈ +35 Elo），200 局的功效仅约 **29%**——
也就是说**本轮跑出「未能证明」是完全可能的，那不等于改动无效，只等于这个实验设计
分辨不了那个量级**。这一点必须在结论里写清楚，不能把「没测出来」说成「证明没有」。

## 五、一个必须同时记录的发现（与本轮结论独立）

核对历史时发现：`scratchpad/run3.js` 里那次 `ttkeep` 打出 22:26 所用的配置是

```js
{ timeMs: 1500, maxDepth: 12, vcfDepth: 14, vctDepth: 0, vctDefDepth: 0, rootFilter: true }
```

`timeMs` 是 LV3 的、`maxDepth`/`vcfDepth`/`rootFilter` 是 LV4 的，而 `vctDepth: 0`
意味着 VCT 被整个关掉——**没有任何一个难度档是这个组合**。按本项目硬规矩之二
（被测配置必须与 `LEVELS` 出厂值逐项一致），**那条 22:26 是无效数据**，
与 PROGRESS「一之二」记载的 +90 Elo 是同一类错误的另一个实例。

它恰好是「TT 跨步保留略偏负、需要 ply 校正来救」这条推理的唯一起点。因此：

- **不得**声称「ply 校正让 ttkeep 从 22:26 翻成 29:19」——两次实验配置、档位、
  VCT 开关全不同，根本不可比。
- 本轮无论结论如何，PROGRESS 里那条 22:26 都要标注为「配置无效，需重测」。
