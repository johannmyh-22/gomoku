# 预登记：`evleafflat` 的对称面——只压平走法排序，叶子分不变

**本文件必须在任何 A/B 数据产生之前提交**，事后不得修改判定口径。

---

## 1. 为什么做这个实验

`PREREG_evleafflat.md`（200 局）测出「只压平叶子分」= −26 Elo，z=−1.06，**未能证明**。
与 `PREREG_evflat.md`（叶子+排序一起压平）的 −168 Elo（z=−6.36）相比，点估计量级
差一个数量级，**提示**排序可能是主要通道——但那份文件已经写明白：这只是两个独立
实验的点估计比较，不是同一次实验里的可加性分解，**不构成证据**。

要坐实，需要对称的另一半：**只压平走法排序，叶子分保持原始 `PSCORE`**。

## 2. 假设

> **H1**：单独压平走法排序（`recomb()` 算的 `SB/SW`），保持叶子评估不变，
> 会造成与 `evflat`（−168 Elo）同量级的棋力差异。
> **H0**：不会——效应量级接近 `evleafflat` 的 −26（即两边都不够，是交互效应）。

## 3. 被测改动（已实现，`load.js` 的 `evordflat`）

复用 `evleafflat` 的 `PSCORE_LEAF=[0,10,10,10,10,10,10,10]`，但只接入 `recomb()`
两处 `s+=PSCORE[t]` 改为 `s+=PSCORE_LEAF[t]`。`SC_FIVE/SC_OFOUR/SC_44/SC_43/SC_33`
这些战术复合判定（真五/活四/双四/四三/双三）**不受影响**（触发条件是棋型计数，
不是分数），只有 fallback 的 `s`（非战术棋型的排序权重）被压平。`touch()`/`make()`
里 `totB/totW`（叶子分）**保持读原始 `PSCORE`**，`evaluate()` 完全不变。
已核对生成源码：`touch()`/`make()` 仍是 `PSCORE`，`recomb()` 已是 `PSCORE_LEAF`，
与 `evleafflat`（反过来）精确对称。

## 4. 前置门槛（已通过）

**非空操作验证**（LV3，3 个开局）：`evordflat vs orig` **3/3 开局全部分歧**
（第 3、4、5 手），比 `evleafflat` 更早分歧。非空操作。

## 5. 实验设计（与 `evleafflat` 完全对齐，便于横向比较）

| 项 | 值 |
|---|---|
| 档位 | LV3 出厂配置 |
| 对打方式 | `evordflat` vs 出厂 `orig` |
| 局数 | **200 局**（100 开局 × 2 换边） |
| 开局种子 | **20260820**（新种子） |
| 对照 | `orig` vs `orig2` 12 局，必须精确 6:6 |
| 分块 | 4 块 × 25 开局 |
| 落盘 | `runs/evordflat_lv3_c1~c4.jsonl` |
| 判定量 | `evordflat` 的胜率与 z 值 |

## 6. 判定规则（先写死，三向对比）

设 z = (W − 100) / 7.07。三个已知/待测点：`evleafflat` z=−1.06（−26 Elo），
`evflat` z=−6.36（−168 Elo）。

| 结果 | 判定 |
|---|---|
| z ≤ −5（量级接近 `evflat`） | **排序坐实是主因**——叶子分对这台引擎基本无关紧要，「接复合分进叶子评估」候选**放弃**，评估侧收窄到走法排序/剪枝效率 |
| −5 < z ≤ −2（量级介于两者之间，或与 `evflat` 相当但不到） | **排序是重要通道，但不是全部**——叶子分仍可能有贡献，两条候选都保留优先级不下调 |
| \|z\| < 2（量级接近 `evleafflat`，同样不显著） | **两边单独测都不显著，是交互效应**——把 `evflat` 的 168 Elo 拆成两个独立变量的思路本身不成立，需要换角度（比如两个变量同时半幅压平，而不是各自单独压满） |
| z ≥ +2 | 反常，需要复核代码，不采信 |

## 7. 禁止操作（照抄前几轮）

1. 不得因结果偏向追加局数。
2. 不得事后改判定阈值。
3. 不得与其他种子数据合并统计。
4. 不得把「机制说得通」当收益证据。
5. 对照不是 6:6 则整轮作废。

## 8. 结果（数据产生后填写）

**LV3、种子 20260820、200 局，2026-08-10 跑完。对照 `orig` vs `orig2` = 6:6 ✅**

| 项 | 值 |
|---|---|
| **`evordflat` vs 出厂 `orig`** | **59 : 141 和 0**（200 局） |
| z | **−5.80σ**，双侧 p < 0.001 |
| 胜率 / Elo | 29.5% ≈ **−151 Elo** |
| 95% CI | 23.2% ~ 35.8% ≈ **−208 ~ −101 Elo** |
| 成对局检查 | 100 对里 55 对换边后胜者改变 → 无空操作特征 |

### 判定（按第 6 节）：**z = −5.80 ≤ −5 → 排序坐实是主因**

## 三个实验拼在一起：完整证据链

| 变体 | 动的变量 | 结果 | 显著性 |
|---|---|---|---|
| `evleafflat` | 只压平**叶子分**，排序不变 | −26 Elo | z=−1.06，**不显著** |
| **`evordflat`** | 只压平**排序**，叶子分不变 | **−151 Elo** | **z=−5.80，高度显著** |
| `evflat`（参照） | 两者一起压平 | −168 Elo | z=−6.36，高度显著 |

−151（只动排序）已经非常接近 −168（两者都动）；−26（只动叶子）在噪声里。
虽然三个是独立实验、不构成严格的可加性证明（−151 + −26 ≈ −177，与 −168 大致
吻合但有重叠区间，不是精确等式），**但方向和量级都指向同一个结论，不需要再猜**：

> **这台引擎的棋力主要来自走法排序把哪些分支送进 alpha-beta，而不是叶子节点
> 打的具体分数。** `evaluate()` 本身相当「粗」也没关系，只要 `recomb()` 算出来的
> `SB/SW` 排序是对的，剪枝就能把好棋找出来；排序一旦被破坏，浅层搜索里对的棋
> 直接搜不到、剪没了。

### 结论：「新特征」往哪儿挂——答案定了

1. **「接复合威胁分进叶子评估」候选：放弃。** 不是「优先级下调」，是本轮数据
   够硬（−5.80σ vs −1.06σ 的对比）直接排除叶子分是大头。
2. **评估侧的改进方向收窄到走法排序 / 剪枝效率**——而不是叶子打分的准确度。
   具体候选（本轮未测，留给下一步）：
   - `SB/SW` 目前的排序信号是否还有遗漏的结构（比如双三/四三之外，更细的
     威胁分层）；
   - 前面 PROGRESS「一之四」测过的 `rootsort`（根节点重排）在 LV5 上是
     0.73σ、未证明——但那是**在「更深不值钱」的饱和结论下测的**（一之七）。
     现在的问题变了：不是「搜得更深值不值钱」，是「同样深度下，排序把对的
     分支放没放到前面」，这是两个不同的机制，`rootsort` 那次 null 不能直接
     套用到这里。
3. **不属于本轮结论的事**：没有测过「具体怎么改排序会更好」，只测出
   「排序是杠杆、叶子分基本不是」。往排序里加什么、怎么加，是下一步的问题。
