# 预登记：拆分叶子评估 vs 走法排序

**本文件必须在任何 A/B 数据产生之前提交**（提交哈希即时间戳），事后不得修改判定口径。

---

## 1. 为什么做这个实验

`PREREG_evflat.md` 测出压平整张权重表 = **−168 Elo**（6.36σ），证明评估轴是活的。
但那个实验**一次动了两个变量**：`PSCORE` 同时喂两个消费者——

- `evaluate()` 用的 `totB/totW`（叶子分，逐字面棋型分数求和）
- `SB/SW`（`recomb()` 算出的走法排序 + 双三/四三/双四复合判定，供根过滤和走法生成用）

压平后两边一起变差，**分不清 168 Elo 主要来自哪一边**。这个口子必须补上，
因为它决定「上新特征」该往哪儿挂：

| 若真相是 | 则 |
|---|---|
| 主要是**走法排序**在起作用 | 叶子评估本身无关紧要，「往 `evaluate()` 加特征」是白费 |
| 主要是**叶子评估**在起作用 | 「把已经算好的复合威胁分（`SC_33`/`SC_43`/`SC_44`）接进叶子评估」这条路有戏 |

（背景：引擎已经算出双三/四三/双四的复合分，但只喂给 `SB/SW`（排序/威胁判定），
从未进入 `evaluate()` 的叶子分——这是当前评估侧唯一已知的、有具体代码路径的改进候选。
值不值得做，取决于本实验的结果。）

## 2. 假设

> **H1**：单独压平叶子评估（`totB/totW`），保持走法排序不变，仍会造成可测量的棋力差异。
> **H0**：不会——168 Elo 主要是排序变差导致的，叶子分本身对这台引擎无关紧要。

## 3. 被测改动（已实现，`load.js` 的 `evleafflat`）

新增独立数组 `PSCORE_LEAF=[0,10,10,10,10,10,10,10]`（与 `evflat` 用的压平值相同），
**只**接入 `touch()`/`make()` 里更新 `totB/totW` 的三处赋值。`recomb()` 计算
`SB[q]/SW[q]` 时**继续读原始 `PSCORE`**，走法排序、根过滤、双三/四三/双四判定
一概不变。已用 patch 后源码核对：`touch()`/`make()` 全部读 `PSCORE_LEAF`，
`recomb()` 仍是 `PSCORE`，隔离干净。

## 4. 前置门槛（已通过）

**非空操作验证**（LV3，3 个开局）：`evleafflat vs orig` 2/3 开局分歧（第 4、11 手），
1/3 开局逐字节相同——**不是全开局都相同**，判定为非空操作，可以进 A/B。

## 5. 实验设计（跑之前定死，不得事后更改）

| 项 | 值 |
|---|---|
| 档位 | **LV3 出厂配置**，逐项照抄 `LEVELS[3]` |
| 对打方式 | `evleafflat` vs 出厂 `orig` |
| 局数 | **200 局**（100 个随机开局 × 2 次换边），固定，不得增减 |
| 开局种子 | **20260819**（全新种子，20260811~20260818 均已用过） |
| 对照 | `orig` vs `orig2` 12 局，**必须精确 6:6** |
| 分块 | 4 块 × 25 开局，边界事先定死、与数据无关 |
| 落盘 | `runs/evleafflat_lv3_c1~c4.jsonl`，含胜负字段与 `job.id` |
| 判定量 | `evleafflat` 的胜率与 z 值 |

## 6. 判定规则（**先写死**，吸取 `PREREG_ev3.md` 那次教训，两个方向分别写）

设 z = (W − 100) / 7.07：

| z | 判定 | 含义 |
|---|---|---|
| **z ≤ −2** | **证实 H1**——叶子分在起作用 | 168 Elo 至少部分来自叶子评估，「接复合分进叶子」值得做；具体值多少后续再测 |
| **\|z\| < 2** | **未能证明**——见下 | |
| **z ≥ +2** | 反常（叶子分被压平反而更强） | 需要复核代码是否有隐藏耦合，不得直接采信 |

`|z| < 2` 时的结论必须这样表述：

> 在 LV3、200 局的分辨力下，单独压平叶子评估**测不出棋力差异**——
> 168 Elo 的大部分或全部来自走法排序变差，不是叶子分本身。

并据此判断是否继续深挖排序侧：

- 若 95% CI 上界（更负的一侧，即更接近 0 的一侧最坏情形）仍容得下 ≥ −50 Elo 的效应
  → 不能排除「叶子分有小效应但本实验功效不足」，「接复合分」这条路留个问号，
  但不因此启动新一轮实验（除非之后有理由认为效应量级值得测）
- 若 CI 把 −50 Elo 都排除（即上界 ≥ −50 Elo 都不在 CI 内，效应确定接近 0）
  → 叶子分对这台引擎基本无关紧要，「接复合分进叶子」这条候选**放弃**，
  评估侧的改进方向收窄到「走法排序 / alpha-beta 剪枝效率」

## 7. 禁止操作（照抄前几轮）

1. 不得因为结果偏向就追加局数。200 局就是 200 局。
2. 不得事后更改判定阈值。
3. 不得与其他种子的数据合并统计。
4. 不得把「机制上说得通」当收益证据。
5. 对照不是 6:6 则整轮作废。

## 8. 结果（数据产生后填写，不得改上面任何一节）

**LV3、种子 20260819、200 局，2026-08-10 跑完。对照 `orig` vs `orig2` = 6:6 ✅**

| 项 | 值 |
|---|---|
| **`evleafflat` vs 出厂 `orig`** | **92 : 107 和 1**（199 局分胜负） |
| z | **−1.06σ**，双侧 p = 0.288 |
| 胜率 / Elo | 46.2% ≈ **−26 Elo** |
| 95% CI | 39.3% ~ 53.2% ≈ **−75 ~ +22 Elo** |
| 成对局检查 | 100 对里 39 对换边后胜者改变 → 无空操作特征 |

### 判定（按第 6 节）：`|z| < 2` → **未能证明** H1

单独压平叶子评估，测不出与出厂有统计显著的棋力差异。

### 续测判断（按第 6 节写死的规则）

CI 是 **[−75, +22]**，**没有排除 −50 Elo 这个效应量级**（−50 落在区间内）。
按预登记：**不能排除叶子分有小效应但本实验功效不足**，问号先留着，
**不因此自动启动新一轮**（第 6 节的条件是「除非之后有理由认为效应量级值得测」）。

### 与 `evflat` 对照，能读出什么、不能读出什么

| 变体 | 动的变量 | 结果 |
|---|---|---|
| `evflat`（上一轮，200 局） | 叶子分 **+** 排序 一起压平 | **−168 Elo**，z=−6.36，铁证 |
| `evleafflat`（本轮，200 局） | **只**压平叶子分，排序不变 | −26 Elo，z=−1.06，不显著 |

**只能提示、不能证明**：单独动叶子分时效应量级（点估计 −26，CI 上探到 −75）
明显小于两者一起动时的 −168，方向上暗示**排序是主要通道**。
但这是**两个独立实验的点估计比较，不是同一次实验里的可加性分解**——
交互效应（叶子分和排序同时变差时是否有超可加的协同破坏）完全没有测，
**不得**声称「168 里有 X 是排序、Y 是叶子分」这种加法拆分。

**要坐实「排序是主因」，需要对称的另一半实验**：只压平排序（`SB/SW` 走
`PSCORE_LEAF`，`totB/totW` 用原始 `PSCORE`），若那个实验打出接近 −168 的效应，
则排序主导的说法才算被独立证实。**本轮未做，留给需要时再测**。

### 对「上新特征」这个问题的回答（本轮能给的最诚实版本）

1. **不能排除**叶子分完全无关紧要（CI 触及 0 附近）。
2. **也不能排除**叶子分有中等效应（CI 另一端到 −75 Elo）。
3. **唯一有把握说的**：`evflat` 的 −168 Elo **不能整个记在叶子分头上**——
   若叶子分单独就能扛起大头，本轮 200 局的功效足够看见（`evflat` 6.36σ 的先例
   说明这条测量台对评估轴很敏感），但没看见。
4. 因此「接复合威胁分进叶子评估」这条具体候选**优先级下调，不是取消**——
   值得做，但不该抱着「一定能找回大头 Elo」的预期去做，且做完必须自己过一次
   独立的 A/B，不能借上面任何一个数字的光。
